# Project Conventions

## File naming

- Code, config, and state files use `snake_case`.
- Batch folders use a time range format:
  `YYYY-MM-DD_HH-MM-SS__to__YYYY-MM-DD_HH-MM-SS`

## Archive rules

- New browser downloads first land in `${DOWNLOADS_DIR}`.
- `${DOWNLOADS_DIR}` is only a staging area. It is not the formal archive.
- After a batch completes, the files are moved into:
  `${RESEARCH_LIBRARY_ROOT}/pdfs/<batch_dir>/`
- The old `${DOWNLOADS_DIR}/ZSXQ-外资研报` path is no longer a supported archive or watcher path.
- Each batch directory includes a `batch_manifest.json` that records:
  - filename
  - source path
  - archive path
  - modified time
  - matched keywords

## Research library rules

- `${RESEARCH_LIBRARY_ROOT}` is the formal data layer.
- `pdfs/` stores the original PDFs.
- `batches/` stores batch manifests.
- `markdown/`, `summaries/`, `state/`, `logs/`, and `cache/` are generated by the processing chain.
- One-off backfill inventories and Feishu document caches must stay outside this repo.

## State rules

- `last_successful_check_at` is the primary lower bound for the next run.
- The current run time is the upper bound.
- If no files are archived, state is still updated after a clean successful scan.
