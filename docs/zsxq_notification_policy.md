# ZSXQ 飞书通知策略

## 目标

群消息只回答五件事：本轮新增了多少 PDF、何时真正开始总结、总结和发布到了
哪个关键里程碑、哪一份飞书文档刚刚可读、批次最终完成或需要处理什么。扫描、
空跑、占锁、退避和逐文件进度保留在运行状态与日志中，不占用群消息。

文档发布和通知是两条身份明确、可恢复的路径：

- 文档 create/append/fetch/授权：`lark-cli ... --as user`；
- 群消息：`lark-cli im +messages-send --as bot --idempotency-key ...`。

没有 OpenClaw 或其他消息 provider fallback。通知失败不能回滚本地摘要或已成功
发布的文档。

## 历史基线

2026-07-08 至 2026-07-14 维护暂停前，共发出 181 条消息。这是迁移前的历史
观测，不是当前运行架构的证据：PDF 摘要 134 条、外研报下载 24 条、中金下载
23 条，其中大量为开始处理、逐文档完成、busy、等待和退避状态。

## 事件矩阵

| 链路状态 | 外研报下载 | 中金下载 | PDF digest |
| --- | --- | --- | --- |
| 正常空跑、无关键词命中 | 静默 | 静默 | 静默 |
| busy、等待下载、安静期、冷却中 | 静默 | 静默 | 静默 |
| 下载成功且有新增 | 发送一条精确 PDF 数量 | 发送一条精确 PDF 数量 | 不适用 |
| 本批首次进入总结 | 不适用 | 不适用 | 发送一条“开始总结”，同一 source window 只发一次 |
| 总结/发布进度 | 不适用 | 不适用 | 仅在综合进度首次跨过 25/50/75% 时发送；一次跨多档只发最高档 |
| 单份飞书文档 fetch/授权校验成功 | 不适用 | 不适用 | 立即发送一条文档链接 |
| 本批全部完成 | 不单独发送 | 不单独发送 | 发送一条终态 Markdown |
| 部分完成、隔离、失败 | 发送一条可行动异常 | 发送一条可行动异常 | 发送一条终态 Markdown |
| 异常恢复 | 发送一次恢复消息 | 发送一次恢复消息 | 后续成功终态即恢复消息 |

综合进度按 `(已总结 + 已发布) / (2 × 本批 PDF 总数)` 计算，卡片始终同时显示
“总结 x/y、发布 x/y”。小批次如果一次 worker 就全部完成，直接发送完成卡，不再
补发 25/50/75% 卡。逐 PDF 完成、重复 tick 和同一里程碑都不会产生消息。

## 消息格式

下载完成后发送一次精确数量：

```markdown
## 知识星球研报｜下载完成

海外研报：本轮新增 **19** 份 PDF，已进入待总结队列。
```

大批次首次跨过关键里程碑时发送一次合并进度：

```markdown
## 知识星球研报｜进度 50%

海外研报｜总结 **12/19**｜发布 **7/19**
```

单份飞书文档完成后仍立即发送紧凑 Markdown，不重复列出文件名：

```markdown
## ✅ 知识星球研报｜文档 2/6 已发布

本批 **10** 篇｜累计发布 **20/51**

文档：[立即查看飞书文档](https://example.invalid/docx/demo-2)
```

全部批次结束后仍发送一条终态 Markdown：

```markdown
## ✅ 知识星球研报｜本轮完成

海外研报｜总结 **19/19**｜发布 **19/19**
```

异常消息只保留异常文件、定位结果、可能原因、下一步动作和已经生成的文档
链接。用户消息不显示本机日志、JSON、缓存或隔离文件路径。

下载窗口在有界浏览器自愈后仍受阻时，每个 `source window + reason code` 只发
一次告警；重复的五分钟重试不会刷屏。告警明确说明窗口没有推进、后续会自动
重试，并给出可检索的结构化诊断码；登录态或配置类错误会改为提示人工动作。

## 可靠性与去重

- 下载、里程碑和 digest 终态共用持久 outbox；消息失败不会重新扫描、OCR、总结或发布。
- 每个远端消息都有稳定幂等键，本地也记录该键的发送状态。
- 下载结果与摘要进度以 durable source window 为 cohort；开始、每个里程碑和完成
  各有独立稳定键，跨多次 quota-bounded worker 仍只发送一次。
- 每份文档通知有独立且稳定的 publication identity；较新的未投递终态会
  supersede 较早的终态，不会替换已经有价值的文档链接。
- 只要仍有待投递的文档通知，任何终态都暂缓投递，保持“文档链接在前、总结在后”。
- 一次任务运行默认只尝试投递一次；失败先持久化，释放本轮后由后续调度重试。
- 退避、认证阻断和发送审计由 outbox 状态记录；发送失败不会占用发布或摘要的
  恢复路径。
- 同一链路只保留最新的未投递结论，避免迟到消息与当前状态相反。
- digest 同一批次、同一终态只投递一次；部分完成后成功会产生新的成功终态键。

## 真相源

下载结果以固定扫描窗口、不可变 scan plan、UUID run manifest 和最终 canonical
result 为准；不采信模型或消息自报数量推进游标。digest 以 pipeline SQLite
state 中的 artifact、stage、publication 和 notification outbox 为准；
`run_status.json`、`last_result.json` 和群消息只是兼容展示层。

publication 的 `remote_written` 说明远端正文可能已经成功，但标题、fetch 或权限
校验尚未完成。恢复只能验证同一 document URL，不能因通知失败或校验中断重复
create/append。预检、自动测试和本策略本身都不会创建真实文档或发送真实消息。
